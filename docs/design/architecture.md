# CashPrediction final UI architecture: one core, three thin renderers

## 0. Verdict

Scores run from 1 (worst) to 5 (best).

| Criterion | A (model-driven) | B (pragmatic) | Why |
|---|---|---|---|
| Verifiable UI identity | 5 | 5 | Both dump real widgets, compare against model goldens, and keep an allow-list. A adds pairwise diffs. B also fails the build on an unused allowance. |
| Behaviour in core | 5 | 5 | Same controller, flows, forms and alerts. A also moves the web file browser into core. |
| Risk to working crash recovery | 3 | 4 | B keeps stores, codecs and dialog hosts as they are. A rewrites every host and adds `java.desktop` to core. |
| Effort | 2 | 4 | A adds about 51k lines and needs 35–40 agent-days. B writes about 30k lines and reuses hosts, popups, widgets, `PngEncoder` and self-test code. |
| Testability | 5 | 4 | A brings `AppClock`, legacy snapshot fixtures and CLI isolation. B brings about 120 `FakeUiPort` flow tests and glyph coverage. |
| 23 JavaFX classes stay meaningful | 4 | 5 | B maps model kinds to classes 1:1 and adds a runtime instantiation probe. |
| Core purity (no toolkit, no AWT) | 2 | 5 | A's `ChartPainter2D` pulls `java.desktop` into core. |

**Decision:** B is the base. It takes these pieces from A:
1. A separate `UiIntents` contract for renderer-to-core calls. It maps 1:1 onto a compact web protocol with four routes (`bootstrap`, `events`, `intent`, `query`) instead of B's 20 REST routes.
2. A single `CommandAvailability` table that returns enabled plus a disabled-hint key.
3. Legacy snapshot fixtures recorded from today's three clients, plus a `FieldCodec.acceptLegacy` compatibility test.
4. One hotkey dispatcher in front of toolkit accelerators (FX scene event filter, Swing `KeyEventDispatcher`, web capture-phase `keydown`). Accelerators are for display only, so a command fires exactly once.
5. The web file chooser as a core form (`FileBrowserForm`). Folder listing moves to `core.io.FolderListing`.
6. `LaunchOptions` and `AppClock` with CLI arguments (`--home`, `--registry-node`, `--today`, `--selftest`, `--selftest-out`, `--selftest-recovery`, `--ui`), so the packaged exes can be isolated.
7. Pairwise client diff in reports, and goldens generated by `ModelUiDriver`.

**Rejected:**
- From A: chart painting in core; rewriting dialog hosts; `WINDOW_MODAL`.
- From B: browser canvas PNG upload (the web server now renders PNG with Java2D, since web already requires `java.desktop`); dropping the what-if amount from the snapshot (an additive optional field keeps it); the 20 REST routes.

## 1. Non-negotiable rules

- **R1. Clients contain toolkit code only.**
  - No Cyrillic string or template literals in `ui-fx/src/main/java`, `ui-swing/src/main/java`, `web/src/main/java` or `web/src/main/resources/web/app/**/*.js`.
  - Comments and one whitelisted `BootstrapFallbackText` per client (a fatal message shown before core loads) are exempt.
  - `NoCyrillicLiteralsTest` in every client module enforces this.
- **R2. Clients never decide.** Enabled, checked, visible, colour, order and texts all come from core models.
- **R3. Crash-recovery formats stay byte-compatible.**
  - `WindowType` names, `contextKeys`, `fieldIds`, purposes, stores and codecs keep their current meaning.
  - The only schema changes are additive: `MainWindowState.whatIfExtra` (an optional string, default empty) and the extra `filters` keys `pastExpanded`, `whatIfIncome`, `whatIfExpense`.
  - Old snapshots must decode; this is tested against the legacy fixtures.
- **R4. The build stays green at every stage.**
  - The legacy UI stays the default until its client passes parity (`--ui core|legacy`, property `cashprediction.ui`).
  - Legacy code is deleted in Stage 4.
- **R5. Core stays free of `javafx.*` and `java.desktop`.**
- **R6. Russian Javadoc and comments everywhere.** Every construction site of the 23 JavaFX classes, and of their Swing and web analogs, carries `// JavaFX: X → Swing: Y → Web: Z`.
- **R7. No external libraries.** Only JDK, OpenJFX and JUnit are used. The portable build still creates only CashMemory.

### 3.2 Commands and hotkeys

- `CommandId` holds every spec id: file.*, edit.*, view.*, tools.*, whatIf.*, recovery.*, help.*, plus the row, total, past-header, card, chart and empty-state actions.
- `record CommandArgs(String rowId, LocalDate date, String cardId, String key, String value)`.
- `CommandAvailability.of(CommandId, CommandArgs, AppState)` returns `Availability(boolean enabled, String hintKey)`. The same table feeds menus, the toolbar, context menus and the hotkey hints.
- `record KeyChord(boolean ctrl, boolean shift, boolean alt, String key)`, where `key` is a physical key name such as `N`, `DIGIT1`, `F2` or `ENTER`.
- `enum FocusScope { MAIN, TABLE, FILTER, TEXT_INPUT, CARD, POPUP }`.
- `HotkeyTable`:
  - `bindings(ClientKind)` returns both desktop and web chords;
  - `shownAccelerator(CommandId, ClientKind)`;
  - `text()` returns spec §7 byte-for-byte.

### 3.3 Menu and toolbar models

Sealed `MenuNode`:
- `Action(id, command, args, text, KeyChord accel, tooltip, enabled)`
- `Check(… checked)`
- `Radio(id, group, … selected)`
- `Separator(id)`
- `Submenu(id, text, tooltip, enabled, children)`
- `Slider(id, command, min, max, majorTick, value, List<String> labels, tooltip, widthPx)`
- `Spinner(id, command, label, min, max, step, value, tooltip, fieldWidthPx, applyDelayMs)`
- `Info(id, text)`, always disabled.

Sealed `ToolbarNode`:
- `SplitButton(id, text, tooltip, main, items)`
- `Toggle(id, command, text, tooltip, selected, group)`
- `MenuButton(id, text, tooltip, Emphasis, items)`
- `FilterField(id, text, prompt, tooltip, widthPx, debounceMs, clearVisible, clearTooltip)`
- `Button(id, command, glyphOrText, tooltip, enabled, Emphasis)`
- `Separator`, `Spacer`

`MenuModels.menuBar/toolbar/contextMenu(AppState, ContextTarget, ClientKind)` are pure functions. They remove adjacent separators and give every node a stable id.

### 3.4 View models

- **Screen:** `MainScreenModel(revision, windowTitle, MenuBarModel, ToolbarModel, SummaryModel, TableModel, ChartModel, StatusModel, ViewMode)` plus `enum ScreenPart { TITLE, MENU, TOOLBAR, SUMMARY, TABLE, CHART, STATUS, MODE }`. The controller hashes each part and re-renders only the parts that changed.
- **Table:** `TableModel` is lazy and never materialises all row texts.
  - Methods: `revision()`, `columns()`, `rowCount()`, `row(i)`, `tooltip(i, col)`, `indexOf(rowId)`, `selectedRowId()`, `scrollToRowId()`, `placeholder()`.
  - It keeps an index array plus an LRU of 2000 rows.
  - `TableRowView(rowId, RowKind, cells, rowStyles, cellStyles, leadingSpan, quickEditable)`.
- **Chart:** `ChartModel.layout(w, h)` returns `ChartScene(width, height, PlotTransform plot, primitives, legend, hits, emptyText, emptyColor)`.
  - Primitives: `Area`, `Polyline`, `Line`, `Box`, `Circle`, `Label(x, y, text, anchor, color, font)`.
  - `PlotTransform.dateAt(x)` uses the formula `from + floor((x-plotX)*dayCount/plotW)`, clamped, which is documented for JS.
  - `ChartModel.dayCard(date)`, `ChartModel.hover(x, y, w, h)`.
- **Summary, status, popups:** `SummaryModel`, `StatusModel` and `StatusSegment(id, text, tooltip, color, grow, visible)` are simple records. `DayCardModel`, `SparklineModel` (normalised 0..1 points) and `CalendarModel` are the popup models.

### 3.7 Controller and flows

- **`AppController(UiPort, AppEnvironment)`** implements `UiIntents`, and `SessionBridge` implements `SnapshotSource` and `RestoreTarget`. `start()` runs `StartupFlow`.
- **`AppState`** is an immutable snapshot: `PlanDocument` view, `ViewState`, selection, `pastExpanded`, filter text, settings, recorder status, open windows (modal chain, single-instance keys), browse folder, and `ClientProfile`.
- **Flows** (as in B, ported from FX primarily, spec where the clients differ):
  - `FileFlow`: new, open, open file, recent, sample, save, save as, rename, CSV, PNG, CashMemory folder.
  - `ExternalChangeGuard`: modification-time checks.
  - `AutosaveService`: 1 s.
  - `SettingsKeeper`: 700 ms.
  - `EditFlow`, `ViewFlow`, `ToolsFlow`, `HelpFlow`.
  - `RecoveryFlow`: snapshot now, show last, clear, simulate.
  - `StartupFlow`: clean start, crashed, already running, `RECORDER_NOT_STARTED` loop.
  - `ExitFlow`.
- **Status messages** and their 10 s expiry are controller state.
- **Modality rule:** while a modal form or alert is open, intents from MAIN, TOOLBAR, MENU and HOTKEY are ignored. Desktop modals are `APPLICATION_MODAL`; web uses `showModal`.
- **Edits** go through `EditFlow.edit(undoKey, args, UnaryOperator<Plan>)`. A model exception is shown in the open form's problem line or as `err.editFailed`.

### 3.8 Environment and session integration

- **`LaunchOptions.parse(args)`.** CLI arguments take priority over system properties:

  | CLI argument | System property |
  |---|---|
  | `--home` | `cashprediction.home` |
  | `--registry-node` | `cashprediction.registry.node` (must start with `ru/cashprediction/`) |
  | `--registry memory` | — |
  | `--today` | `cashprediction.today` |
  | `--ui core\|legacy` | — |
  | `--selftest <scenario>` | `cashprediction.selftest` |
  | `--selftest-out <dir>` | `cashprediction.selftest.log` |
  | `--selftest-recovery registry\|xml\|none\|already-ok` | `cashprediction.selftest.recovery` |
  | `--test-api` (web) | — |
  | `--no-browser`, `--no-window` (web) | — |

  Existing property names are kept.
- **`RegistrySessionStore.forClient(client)`** reads the node property. The default `ru/cashprediction/session/` is unchanged, and a new `forClient(client, nodePrefix)` overload is added.
- **`SessionStores.forClient`** returns:
  - FX: registry `fx` + `session-fx.xml`;
  - Swing: registry `swing` + `session-swing.xml`;
  - Web: `web-session.md`.
- **`CoreWindowFactory implements WindowFactory`:**
  1. `FormCatalog.forRestore(ws, state)` builds the form or fails with a `restore.warn.*` text.
  2. `FormSession.applyState`.
  3. `port.openForm` with `Placement(ownerId, bounds)`.
  4. `onShown` fires when the renderer calls `shown()`.
     S2 uses `FormSession.whenShown(callback)`: a late subscriber is called immediately if the client has
     already reported `shown()`. Creating a window handle is not evidence that the window was shown.
  Menus use the same `FormRequest` path, so restored windows behave exactly like fresh ones.
- **S2 additive flow contract:** `FlowContext.showMain(MainWindowState)` is the shared entry for startup
  and restore. `AppController` builds the screen, delegates to `UiPort.showMain` once and enables subsequent
  partial rendering. `refresh()` before this entry must not render a hidden main window.
  `FlowContext.showRestoredAlert(spec, restored, onShown, onButton)` preserves the original alert id and owner.
  `AlertSession.whenShown` provides the same real-show handshake as forms; the restore factory must not replace
  an alert with a form or exclude alerts from compatibility verification.
  `FormLogic.onFieldChanged(fieldId, committed, state, context)` is an additive default hook for dependent
  fields. It handles the server chooser's disk/path transition in core, without browser-only decision logic.
- **`SessionBridge.captureMain`** records bounds from the port, view, period, flags, filter text, selection, the extra `filters` keys and `whatIfExtra`. `applyMain` restores them all.
- **`WindowType.title()`:** ADJUSTMENT_EDITOR becomes «Корректировка события». This is a text-only change; titles are not persisted, and a codec test proves it.

### 3.9 Threading

- The controller is confined to one thread: the FX Application thread, the Swing EDT, or the web `ControllerThread` (a single-thread executor that replaces `ServerUiExecutor`).
- All port callbacks complete on that thread. Timers re-post through `UiExecutor`.
- Each callback fires once (an `AtomicBoolean` guard in the hosts and in `WebUiPort`).
- Tests assert `executor.isUiThread()` at every `UiIntents` entry.
- S3 terminal lifecycle: `AppController` decorates its supplied `UiPort`, caches the profile/executor/scheduler,
  and prevents queued timer tasks, late chooser/alert replies and intents from calling the client after exit.
  Renderer bootstrap and widget drivers retain their originally constructed concrete port; `controller.port()`
  is a lifecycle boundary, not a concrete renderer to cast. Cancellation of exit leaves delivery active.

## 5. Web protocol (all routes require the existing token; JSON is produced by `UiJson` from core records, sealed kinds become `kind`, dates are ISO)

```
GET  /                         index.html (pre-bootstrap texts injected server-side), /app/*.js, /app/tokens.css (TokenCss.webCss)
GET  /api/ui/bootstrap?tab=<uuid>        -> {seq, client:"web", testApi, profile, screen:MainScreenModel(all parts, table without rows),
                                              hotkeys:[HotkeyBinding web], windows:[form.open|alert.open effects in open order],
                                              overlay:null|{kind:STOPPED|CRASHED|RECOVERY_PENDING}, texts:{offline.*}}
GET  /api/ui/events?tab=&after=<seq>     -> long-poll <=25 s: {seq, effects:[…]} | {resync:true} (after older than ring)
POST /api/ui/intent  {tab, afterSeq, intent:{type,…}} -> {seq, effects:[all effects with seq>afterSeq]}   (503 {busy:true} after 5 s; effects then come via poll)
POST /api/ui/query   {type,…}                        -> {result} | {stale:true, rev}
POST /api/test/result, /api/test/dump                 (only with --test-api)
```

**Intent types:**
- main-window intents: `command{command,args,source}`, `key{chord,scope}`, `selectRow{rowId}`, `activateRow{rowId,columnId,how}`, `filterText{text}`, `sliderCommit{itemId,value}`, `spinnerCommit{itemId,value}`, `mainGeometry{bounds,maximized}`, `menuHover{itemId}`, `closeMain`;

- alert display acknowledgement: `alertShown{windowId}`; only actual DOM visibility acknowledges `AlertSession.whenShown`, not effect publication or handle creation. Closed and unknown ids are ignored; duplicate acknowledgements are idempotent.
- other: `alertButton{alertId,buttonId}`, `clientError{message,stack}`.

**Query types:** `contextMenu{target}`, `tooltip{rev,index,columnId}`, `rows{rev,from,count<=300}`, `chartScene{rev,w,h}`, `dayCard{date}`, `sparkline{cardId}`, `calendar{month,selected}`.

**Effect types:**
- `screen{revision,parts}`;
- `form.open{window:{id,ownerId,modal,placement,spec,view}}`, `form.view{windowId,view,echoOf:{tab,clientRev}}`, `form.close{windowId}`, `form.front{windowId}`;
