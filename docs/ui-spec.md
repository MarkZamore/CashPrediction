# CashPrediction: единая спецификация интерфейса (JavaFX = Swing = Web)

Версия 2. Единственный источник правды. Всё, что здесь не описано, клиент не показывает. Исполняемая форма спецификации — эталонные дампы `core/src/test/resources/ui-golden/` (§9); изменение спецификации и эталона делается одним коммитом.

## Изменения версии 2 относительно версии 1
1. Модели ядра названы как в архитектуре: `MenuBarModel`/`MenuNode`, `ToolbarModel`, `SummaryModel`, `TableModel`, `ChartModel`/`ChartScene`, `StatusModel`, `FormSpec`/`FormView`, `AlertSpec`, `CommandId`, `CommandAvailability`, `HotkeyTable`, `UiText`, `UiFormats`, `SamplePlan`. Каталог текстов — `core/src/main/resources/ru/cashprediction/core/ui/text/*.properties` (UTF-8, по файлу на область).
2. PNG графика во всех клиентах рисуется из одной сцены `ChartScene` 1200×700. Web рисует PNG на сервере (Java2D), браузер не участвует.
3. Модальное окно блокирует всё приложение, включая немодальный калькулятор цели (FX/SW — APPLICATION_MODAL, Web — `showModal`). Пока открыто модальное окно, команды главного окна ядро игнорирует.
4. Выбор файлов в Web — окно ядра «Выбор файла» (§6.21) с точными текстами; в дампе сравнивается запрос выбора, а не вид окна.
5. Горячие клавиши обрабатывает один диспетчер ядра; ускорители в меню только отображаются (срабатывание ровно один раз).
6. «Что-если» полностью попадает в снимок: флажки — ключи `whatIfIncome`, `whatIfExpense` карты `filters`, доп. экономия — новое необязательное поле `whatIfExtra` главного окна; `pastExpanded` — ключ `filters`.
7. Стрелка «▾» у кнопок-меню не входит в текст модели: FX/SW рисуют встроенную стрелку, Web — глиф ▾.
8. Исправлены ссылки (§8.3 подсказки, §8.6 ошибки); уточнены доступность `edit.edit`, слайдер при горизонте > 120, заголовок окна корректировки «Корректировка события» (и `WindowType.title()`).
9. Шрифты Swing создаются как составные (`StyleContext.getFont` → `FontUIResource`), чтобы глифы ⟲ ◎ ⇄ ≡ Δ ▦ не превращались в квадраты.
10. Добавлены §9 (порядок автоматической проверки) и §10 (закрытый список допустимых различий).

**Условные обозначения**
- `ключ` = «текст»: строка каталога ядра. Доступ `UiText.get(key, args…)`, подстановки `{0}`, `{1}` (собственная подстановка, не `MessageFormat`).
- **[НОВОЕ]** — решение, которого не было ни в одном прежнем клиенте.
- **[WEB]** — неустранимое отличие браузера (все перечислены в §10).
- **[FX] / [SW]** — отличие только в технике; пользователь его не видит.

**Форматы** (только ядро: `Money`, `UiFormats`, `DateFormats`, `RuText`)
- `Money.format()`: «80 000,00». `format(cur)`: «80 000,00 ₽». `formatSigned()`: «+80 000,00» / «-45 000,00»; ноль без знака.
- `whole(cur)`: «177 000 ₽». `wholeSigned`: «+46 654».
- `compact`: ≥1 000 000 → «1,5 млн» (одна цифра после запятой, нулевую дробь опускать: «2 млн»); ≥10 000 → «896 тыс»; иначе «950».
- Даты «05.10.2026»; месяц «Октябрь 2026»; день недели «пн» / «понедельник».
- `UiFormats.horizonLabel`: «12 месяцев», «2 года», «до 31.08.2027». ISO-дата в интерфейсе запрещена.

**Принцип тонкого клиента.** Ядро отдаёт готовые модели; клиент только рисует модель и передаёт действия пользователя в ядро (`UiIntents`, события `FormSession`). Web получает те же модели в JSON. Клиент не содержит русских строковых литералов (кроме аварийного текста до загрузки ядра) и не решает, что доступно, отмечено, видно, какого цвета и в каком порядке.

## 2. Главное окно
- **Заголовок:** `main.title` «CashPrediction — {0}»; при несохранённых изменениях `main.title.dirty` «CashPrediction — {0} *» (web: `document.title`). План без файла называется «Мой план» (первое свободное имя: «Мой план», «Мой план 2», …).
- **Размер:** по умолчанию 1200×800 по центру экрана, минимум 900×600. [WEB] вкладка браузера, минимум не навязывается, раскладка та же.
- **Области** сверху вниз: 1) строка меню; 2) тулбар 36px; 3) панель сводки; 4) центр: таблица или график, занимает всё оставшееся; 5) строка состояния 24px.
- **Панель сводки:** 9 карточек в ряд одинаковой ширины, минимум 118px, максимум не ограничен. При нехватке ширины перенос на второй ряд (Web flex-wrap, FX `FlowPane` с привязкой ширины, SW WrapLayout). Горизонтальной прокрутки нет. Скрыта целиком, когда «Панель сводки» выключена.
- **Закрытие:** крестик, Alt+F4 и «Файл → Выход» идут одним путём (§6.32).
- **Восстановление размера:** границы из снимка берутся, если окно ≥ 400×300 и видно на каком-либо экране; признак «развёрнуто» тоже восстанавливается.
- **Фокус при открытии:** таблица.
- **Модальность:** пока открыто модальное окно, главное окно и немодальные окна не принимают ввод и горячие клавиши.

## 3. Строка меню

Шесть меню: Файл | Правка | Вид | Инструменты | Восстановление | Справка. Строятся из `MenuBarModel`; у каждого узла стабильный id (`file`, `file.new`, `file.recent.0`, `view.period.M3`), он же привязан к виджету и ключ дампа.

**Правила**
- Мнемоник (подчёркнутых букв) нет ни в одном клиенте.
- У каждого пункта есть подсказка `menu.<id>.tip`: Tooltip на пункте (FX — через `MenuItem.getStyleableNode()` при показе меню; SW — `setToolTipText`; Web — div-подсказка) и одновременно текст в сегменте «Сообщение» строки состояния, пока пункт под указателем.
- Колонка «Desktop» — ускоритель JavaFX/Swing, «Web» — ускоритель браузера. Оба сочетания работают во всех клиентах (§7); в меню показывается сочетание своей платформы. Ускорители только отображаются: нажатие обрабатывает диспетчер ядра (`HotkeyTable`), поэтому команда срабатывает ровно один раз.
- Отключённый пункт виден серым. Если сочетание вызвано для отключённой команды, в строку состояния выводится `status.hint.<условие>` (§8.3), цвет info.
- Пустых соседних разделителей нет (удаляет ядро).

### 5.3 График (`ChartModel` → `ChartScene`)
Ядро вычисляет все координаты и подписи (сцена примитивов: область, ломаная, линия, прямоугольник, круг, текст с якорем, зоны подсказок, преобразование x → дата). Клиенты только рисуют: FX `Canvas`, SW `Graphics2D`, Web SVG.
- **Область:** фон `bg.surface`, поля слева 80, справа 24, сверху 28 (легенда), снизу 32.
- **Диапазон:** от начала прогноза до `view.periodEnd`. Заголовок не рисуется; сведения о диапазоне в легенде.
- **Прогноз не рассчитан:** в центре «Прогноз не рассчитан: {0}» (`expense`). Меньше 2 точек: `chart.noData` «Недостаточно данных для графика».

**Ось Y** (`ChartScale`): шаги 1/2/5×10ⁿ, около 6 делений; диапазон включает 0, подушку (если > 0) и цель. Горизонтальная сетка `grid`. Подписи целыми с группировкой пробелом («150 000»), выровнены вправо до оси, `text.muted` 11px.

**Ось X:** вертикальная сетка на первом числе каждого месяца. Подписи «янв», «фев», …; в январе и на первой подписи «янв 2026». Шаг подписей: каждый месяц при ≤ 12 месяцах, каждый 2-й при ≤ 24, 6-й при ≤ 48, 12-й иначе.

**Серии и линии** в порядке рисования:
1. **Столбцы итогов месяцев** (флаг chartBars): полоса внизу высотой min(110, 22 % высоты), ось полосы по середине, подпись `chart.barsAxis` «итог мес.». Прямоугольник на 70 % ширины месяца, высота пропорциональна |net|/max|net|; `income`/`expense`, непрозрачность 0,45. Подсказка: «Октябрь 2026», «Итог: +X ₽», «Доходы: X ₽», «Расходы: X ₽», «Баланс на конец: X ₽».
2. **Заливка** под линией баланса до нуля: `accent`, непрозрачность 0,10.
3. **Баланс:** ступенчатая линия (сначала горизонталь, затем вертикаль), `accent` 2px, до 1500 точек (`ChartSeries.sample`).
4. **Ноль:** `line.zero`, подпись «0» справа над линией.
5. **Подушка** (если > 0): `line.cushion`, подпись `chart.cushion` «подушка 50 000».
6. **Цель** (если задана): `line.goal`, подпись `chart.goal` «цель «Отпуск» 300 000».
7. **Сегодня** (если в диапазоне): вертикаль `line.today`, подпись `chart.today` «сегодня» сверху.
8. **Маркеры** (флаг chartMarkers): круг r = 3,5 на день, в котором есть видимые (с учётом фильтров) непропущенные события, кроме START; центр на балансе конца дня. Заливка `income` (только доходы), `expense` (только расходы), `marker.mixed` (оба); обводка белая 1px. Не больше 400; при превышении маркеры не рисуются, в легенде `chart.tooManyMarkers` «Маркеры: слишком много событий — уменьшите период». Подсказка маркера: «dd.MM.yyyy», строки «+80 000,00 ₽ — Зарплата», «Баланс: X ₽».

**Легенда** над графиком, 12px, образцы цвета: «Баланс, dd.MM.yyyy — dd.MM.yyyy»; «Ноль»; «Подушка» (если есть); «Цель» (если есть); «Сегодня» (если в диапазоне); «Доход», «Расход», «Доход и расход» (если маркеры); «Итог месяца» (если столбцы).
Подсказки: «Баланс на конец каждого дня»; «Нулевой баланс: ниже этой линии денег не хватает»; «Подушка безопасности: {format(cur)}»; «Цель «{title}»: {format(cur)}, достигается dd.MM.yyyy» (или «, не достигается»); «Сегодня, dd.MM.yyyy: левее — прошедшие дни»; «Дни с доходами»; «Дни с расходами»; «Дни с доходами и расходами»; «Доходы минус расходы за месяц».

**Наведение** внутри области построения: пунктирная вертикаль `text.muted`, точка `accent` r = 4,5 на линии; карточка дня (§5.6.2) у указателя +16/+16. За пределами области всё скрывается.

### 5.4 Строка состояния (`StatusModel`)
Высота 24, фон `bg.window`, верхняя рамка `border`, `font.small`. Сегменты разделены вертикальными чертами; невидимый сегмент не оставляет черты.
1. **file:** «Файл: {имя.md}» или «Файл: не сохранён». Подсказка: полный путь или `status.file.tip.none`.
2. **dirty:** «● есть несохранённые изменения» (`warn`), «сохранён» (`text.muted`) или «без изменений» (план без файла и без правок, `text.muted`).
3. **rows:** «Строк: {N}» — только строки событий (без итогов и PAST_HEADER).
4. **horizon:** «Горизонт: {horizonLabel} (до dd.MM.yyyy)»; для UNTIL «Горизонт: до dd.MM.yyyy».
5. **message** (растягивается): 10 с, цвет по уровню — info `text.primary`, success `income`, warn `warn`, error `expense`. При наведении на пункт меню здесь его подсказка. Постоянные сообщения держатся, пока причина не исчезнет: «Настройки не сохранены: {0}», «Прогноз не рассчитан: {0}».

8. **session:** до первой записи «Снимок сеанса: ещё не записан»; затем «Снимок: реестр ✓ 10:15:30 | XML ✓ 10:15:31», при сбое вместо времени «✗» и сегмент `expense`; [WEB] «Снимок: сервер ✓ 10:15:30». Второй экземпляр: «Запись сеанса отключена (второй экземпляр)». Ожидание решения о восстановлении: «Ожидает решения о восстановлении». Подсказка: по строке на хранилище («Реестр: записано 10:15:30» / «XML: ошибка — {msg}»); для отключённой записи «Снимки сеанса пишет первый запущенный экземпляр CashPrediction».

Всплывающих уведомлений (toast) и баннеров нет ни в одном клиенте. Все «тихие» успехи идут в сегмент message.

## 6. Диалоги

### 6.0 Общие правила

**Каркас формы** (`FormSpec` + `FormView`; FX `Dialog<String>` + `AppDialogPane`; SW `SwingDialog` + `SwingDialogPane`; Web `<dialog>`)
1. **Заголовок окна** (`dialog.<id>.title`).
2. **Полоса заголовка:** значок 26px слева; текст `font.header`, до 3 строк; разделитель снизу.
3. **Контент — сетка формы:** подписи выровнены вправо, с «:» в конце, минимальная ширина 150; промежутки 10 по горизонтали и 8 по вертикали; раздел = разделитель + жирная подпись; «широкая» строка занимает обе колонки.
4. **Строка проблем** (место резервируется всегда): первая ошибка «✖ {текст}» цвета `expense`; если ошибок нет — первое предупреждение «⚠ {текст}» цвета `warn`.
5. **Ссылка подробностей** (если есть подробности): `details.show` «Подробности ▸» / `details.hide` «Скрыть подробности ▾». Подробности — моноширинное поле 80×16, только чтение.
6. **Панель кнопок.** Порядок задан явно, без сортировки по ролям: кнопки роли LEFT прижаты влево; остальные справа в порядке спецификации; CANCEL всегда последняя. [FX] `ButtonBar.setButtonOrder(ButtonBar.BUTTON_ORDER_NONE)` плюс растущая распорка после LEFT.

**Роли кнопок:** OK (подтверждающая, по умолчанию Enter, выделена `accent`), CANCEL (Esc и крестик), OTHER, LEFT, BACK, NEXT, FINISH.

**Поведение**
- Валидация при каждом изменении поля (Web — запрос к серверу не чаще раза в 120 мс; поздний ответ не перезаписывает более новый ввод). OK/FINISH отключены, пока есть ошибка. Предупреждения не блокируют.
- Ошибка ядра при применении показывается в строке проблем, диалог остаётся открытым.
- Модальность: модальное окно блокирует всё приложение. Немодальные: калькулятор цели и быстрая правка. Владелец (главное окно или родительский диалог) задаёт положение и порядок закрытия.
- Размер: по содержимому, не меньше ширины §1.3; изменяемый; помещается в видимую область экрана; центр над владельцем. [WEB] немодальное окно — у правого края, y = 96.
- Восстанавливаемые окна регистрируются в записи сеанса после показа; поля и границы передаются в запись сразу (запись сама откладывает сохранение).

**Закрытый набор элементов формы** (`FieldKind`)
- `text`: однострочное поле.
- `multiline`: N строк, перенос.
- `money`: справа выровнено, подсказка «0,00», переформатируется при потере фокуса («80000» → «80 000,00»); принимает «80000», «80 000,5», «80000.50».
- `date`: поле + календарь (§5.6.5), подсказка «ДД.ММ.ГГГГ», принимает также «ГГГГ-ММ-ДД», при потере фокуса переформатируется в «ДД.ММ.ГГГГ».
- `spinner(min..max)`: целое.
- `choice`: выпадающий список.
- `editableChoice`: список с вводом.
- `check`.
- `radio`: группа, горизонтальная или вертикальная.
- `list`: список с выбором (N видимых строк).
- `preview`: только чтение, список или текст.
- `resultLines`: строки результата.
- `button`.

Некорректный ввод хранится как есть (в том числе в снимке) и восстанавливается дословно.

- `val.money.invalid` «Поле «{0}»: некорректная сумма «{1}»»
- `val.money.positive` «Поле «{0}»: сумма должна быть больше нуля»
- `val.money.tooBig` «Поле «{0}»: слишком большая сумма»
- `val.money.nonNegative` «Поле «{0}»: сумма не может быть отрицательной»
- `val.date.required` «Укажите дату в поле «{0}» (ДД.ММ.ГГГГ)»
- `val.date.invalid` «Поле «{0}»: некорректная дата (ДД.ММ.ГГГГ)»
- `val.text.required` «Заполните поле «{0}»»

**Имя плана** (`PlanValidator.checkPlanName`): «Имя плана не может быть пустым»; «Имя плана длиннее 80 символов»; «Имя плана не может содержать символы \ / : * ? " < > |»; «Имя плана не может содержать управляющие символы»; «Имя плана не может заканчиваться точкой»; «Имя «{0}» зарезервировано программой для служебного файла»; «Имя «{0}» зарезервировано Windows»; `val.plan.exists` «План «{0}» уже есть в CashMemory — выберите другое имя».

**Каркас сообщения** (`AlertSpec`; FX `Alert`, SW `SwingAlert`, Web `<dialog>`)
- Тип INFORMATION / WARNING / ERROR / CONFIRMATION. Заголовок окна, заголовок-текст (жирно), содержимое (переводы строк сохраняются), подробности (свёрнуты или раскрыты — указано в каждом случае).
- Минимальная ширина 460.
- Заголовок окна по умолчанию: INFORMATION и WARNING — «CashPrediction»; ERROR — «CashPrediction — ошибка».
- Кнопка по умолчанию «ОК» (кириллица), роль OK.
- Ошибка с исключением: содержимое = сообщение или простое имя класса; подробности = стек, свёрнуты.

**Выбор файлов** (`FileChooserSpec`; не восстанавливаются)

- SW: `JFileChooser`, русские ключи `UIManager`: «Открыть», «Сохранить», «Отмена», «Папка:», «Имя файла:», «Тип файлов:», «Все файлы», «Вверх», «Домой», «Новая папка», «Список», «Таблица».
- Web: окно ядра «Выбор файла» (§6.21).

- **Окно сервера** (Swing, лаунчер) не входит в общий интерфейс.

### 6.31 Сохранение, автосохранение
- **Ctrl+S:** план с файлом → проверка §6.14 → запись → статус `status.msg.saved`; план без файла → если `CashMemory/<имя>.md` существует, §6.13; иначе запись.
- Ошибка записи: ERROR `err.save` «Не удалось сохранить план в «{path}»» + стек.
- **Автосохранение:** через 1 с после изменения, если включено и план изменён. Файл есть → запись или §6.14. Файла нет → запись, только если `<имя>.md` не существует; иначе тихо пропустить и показать статус `status.msg.autosaveSkipped`.
- Настройки пишутся через 700 мс; ошибка — постоянный статус `status.msg.settingsFailed`.

### 6.32 Выход
1. Снимок сеанса немедленно.
2. Если есть изменения → §6.12; «Отмена» или неудачное сохранение прерывают выход.
3. Остановить автосохранение, записать настройки, закрыть сеанс чисто (маркер closed), закрыть окно и процесс.
- [WEB] команда `file.exit` через протокол, затем экран §6.30 и остановка сервера.

### 6.33 Необработанная ошибка
- Снимок сохраняется.
- ERROR «CashPrediction — ошибка» / «Непредвиденная ошибка. Сеанс сохранён, при следующем запуске его можно восстановить.» / «{Класс}: {сообщение | без описания}». Подробности свёрнуты: стек.
- Кнопка [Закрыть программу] → halt(2); следующий запуск покажет §6.29.
- Повторная ошибка при открытом окне пишется только в stderr.
- [WEB] ошибка JS не роняет сервер: то же окно с кнопками [Перезагрузить страницу] (OK) [Продолжить работу] (CANCEL). Ошибка сервера: снимок + halt(2), вкладка переходит на экран потери связи.

## 9. Автоматическая проверка одинаковости

1. **Контракт-тесты ядра** (сборка по умолчанию): модели меню, тулбара, контекстных меню, карточек, таблицы, графика, строки состояния, каждая форма и каждое сообщение, `HotkeyTable`, каталог текстов.
2. **Эталон:** сценарии `core/src/main/resources/ru/cashprediction/core/ui/scenarios/*.cps` выполняются ядром без интерфейса (`ModelUiDriver` + `FakeUiPort`); результат — эталонные дампы `core/src/test/resources/ui-golden/<сценарий>/<шаг>.json`. Сегодня фиксируется `--today 2026-09-13`.
3. **Дамп клиента** строится из настоящих виджетов (тексты, доступность, отметки, подсказки, ускорители, цвета как токены, границы областей, открытые окна и меню), а не из модели. Каждый клиент запускает те же сценарии своим драйвером: `--selftest <сценарий> --selftest-out <папка>`.
4. **Сравнение** (`ui-parity`, профиль `ui-tests`): каждый клиент ≡ эталон с учётом только §10; клиенты попарно (границы ±4 px); неиспользуемое исключение §10 — тоже ошибка.
5. **Визуальная проверка:** снимки экрана 1200×800 при масштабе 1,0; автоматически — цвета фона областей (ΔE < 6 к токену), положения карточек, колонок, кнопок (±4 px); вручную — отчёт с тремя снимками рядом перед выпуском.
6. **Изоляция:** `--home`, `--registry-node ru/cashprediction/selftest/<uuid>` (узел удаляется после теста), `--today`.
