# Перепись настоящих классов FX в S3

`ClassUsageTest` запускает 18 встроенных сценариев и дополнительный
`census-directory-chooser.cps`: `file.cashMemory`, локализованная кнопка
`button.otherFolder`, запрос выбора папки и `chooser cancel`.
Программа получает отдельную CashMemory и узел `selftest/<uuid>`.
Лаунчер завершает дерево процессов; узел удаляется в finally, настоящие
узлы сеанса сравниваются с исходным состоянием.

Каждый запуск использует копии jar. Перепись читается только из настоящих
дампов FX. Наличие имени в OpenJFX jar подтверждает допустимость имени,
но не создание экземпляра. Требуются положительные числа всех 23 классов,
включая `ContextMenuEvent`, точные метаданные каждого дампа и точный набор
шагов dump. Числа не складываются между накопительными снимками.
Все строки сценария должны иметь один правильный OK и финальный DONE.
Сбой запуска остаётся ошибкой даже при суммарных 23/23. Диагностический
фильтр сценариев не подтверждает полную матрицу: обязательны все 18
сценариев и проба папки.

После сборки клиентских jar владельцами:

```powershell
mvn -o -B -Pui-tests -pl ui-parity test '-Dtest=ClassUsageTest' '-Dparity.realClients=true' '-Dparity.clients=fx'
```

Отдельный ограниченный реальный повтор выбора папки:

```powershell
mvn -o -B -Pui-tests -pl ui-parity test '-Dtest=DirectoryChooserProbeTest' '-Dparity.realClients=true' '-Dparity.clients=fx'
```

Последний полный запуск 02.10.2026 получил реальные положительные 23/23,
в том числе DirectoryChooser после отмены. Полная проверка осталась красной:
s11: `rowclick past@group` на строках 5 и 7 даёт NoSuchElementException:
пустой columnId по контракту означает колонку «Операция», но драйвер
ищет ячейку с буквальным пустым id;
s16: процесс выходит с кодом 0 после последнего дампа, до финального DONE;
s17/s18: NPE в FxAlerts.initOwner, поскольку у владельца ещё нет Scene.
Это дефекты клиентского запуска/драйвера, их исправляет владелец FX.
