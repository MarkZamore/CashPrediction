# Подключение настоящих рендереров S3

Владелец этого изменения меняет только `ui-parity/**`. Общие Maven-сборки и
реальная матрица 18 x 3 выполняются ведущим последовательно. Golden и allowances
не изменены. Тесты инфраструктуры и синтетическая страница Edge не доказывают
паритет приложения.

## Обязательные точки подключения рендереров

FX/Swing запускают штатный `SelfTestRunner` с драйвером настоящих виджетов при
`--selftest <имя> --selftest-out <папка>`; интерфейс ядра используется по умолчанию. Раннер работает вне потока
интерфейса; его драйвер исполняет операции в потоке интерфейса, ждёт debounce,
читает виджеты и пишет их дампы. После выполнения публикуется `SELFTEST DONE`.
Сборщик включает в сообщение об ошибке точные строки `SELFTEST ... FAIL`.

Web запускается с `--no-browser --no-window --test-api`. После готовности
HTTP сервер ровно один раз печатает в stdout:

```text
PARITY_URL http://127.0.0.1:<port>/app.html?t=<token>
```

Сборщик принимает только HTTP loopback с явным портом и токеном, без userinfo,
фрагмента и перенаправления. Он открывает этот адрес в собственном профиле Edge,
проверяет viewport 1200x800 и через JDK CDP ждёт тестовый порт страницы:

```text
window.cpParityTestApi.supported = ["Sample", "Menu", ...]
execute({kind, args: <UiJson tree команды>}) -> Promise<{ok:true}>
awaitIdle({timeoutMs}) -> Promise<{ok:true}>
dump({step}) -> Promise<{ok:true,value:<UiDump из DOM>}>
takeStep({}) -> {ok:true,value:<следующий test.step или null>}
```

`takeStep` - новая точка подключения относительно README-S2. Страница складывает
в неё test.step из штатной упорядоченной доставки эффектов, а сборщик единолично
забирает шаги. Страница не исполняет этот же эффект повторно и не отправляет
результаты самостоятельно. Порт и очередь отсутствуют без bootstrap.testApi.
Результат takeStep содержит `{type:"test.step",n,command}` целиком.

`TestApiBridge` исполняет команду через DOM API и ждёт idle. Для dump отправляет
`POST /api/test/dump {n,dump}`, затем `POST /api/test/result {n,ok,message}`.
Все запросы содержат `X-Token`. Ответ - 204 либо 200 с явным `{ok:true}`;
ошибка транспорта прерывает сбор. Дубли и перестановки номеров отклоняются до
исполнения. Номера могут быть номерами строк cps, поэтому соседние значения
не обязаны отличаться на единицу. Сборщик требует в журнале результат каждой
строки сценария в точном порядке: один DONE не скрывает пропущенные операции.
API сообщает ошибку, если не поддерживает команду; неподдержанная команда
никогда не подтверждается успешной. Promise ограничен сроком на уровне CDP.

Wait, Signal и запись файлов сценария остаются обязанностью серверного
SelfTestRunner. Встроенные 18 сценариев не содержат shot и menus. Визуальные
сценарии используют подключённый путь Shot: мост сначала читает живой DOM,
затем захватывает PNG и отправляет `/api/test/shot {n,dump,png}` до подтверждения
шага. Сервер требует оба артефакта, сохраняет `<step>.raw.json` без округления
и `<step>.png`. Наблюдение не закрывает меню и не удаляет его DOM-узлы.
Обычные нормализованные дампы остаются отдельными `<step>.json`; raw-sidecar
не участвует в сравнении с golden и не может заменить обязательный дамп.

Регрессия согласованности контекстного меню запускает настоящий сервер и Edge:

```powershell
mvn -B -Pui-tests -pl ui-parity "-Dtest=WebContextShotIT" "-Dparity.web.contextShot=true" test
```

Перед запуском нужны собранные production JAR (`mvn -B install`). Проверка
сохраняет raw JSON и штатный PNG, требует прежние DOM-узлы и фокус, затем
доказывает вклад меню в изображение контрольным снимком с временно скрытым
тем же меню. При явном включении отсутствие браузера или результата - ошибка,
не успешный пропуск. Артефакты остаются в `target/parity/web-context-shot-*`.

## Изолированные исходные данные

`ScenarioFixtures` использует штатные SamplePlan, формы, markdown и SessionStore
для подготовки данных, не создаёт UI-дампы и не вызывает ModelUiDriver/ModelDump.

- s14: в отдельном потоке ждёт `<selftest-out>/external-change`, увеличивает mtime
  созданного сценарием файла примера на 2000 мс, затем удаляет сигнал. Содержимое
  файла сохраняется. Ошибка и timeout выходят в отчёт сборщика.
- s17: заранее сохраняет пример, settings с lastPlan/recentPlans и аварийный
  снимок на 13.09.2026 12:00:00 в часовом поясе JVM. Окно w1 PLAN_SETTINGS
  содержит startBalance=bad. FX/Swing получают одинаковые registry/XML-снимки,
  Web - серверный markdown-снимок. Маркер с pid=0 означает завершённую JVM.
  `--selftest-recovery` не передаётся, чтобы диалог действительно появился.
- s18: сохраняет пример и снимок без окон, запускает отдельную ограниченную
  десятью минутами JVM, записывает её живой pid/startInstant в маркер. Это
  реальный владелец маркера для CrashDetector, а не рендерер первого окна.
  `close` завершает всё дерево вспомогательной JVM. Проверка двух настоящих
  экземпляров приложения остаётся задачей AlreadyRunningE2ETest S4.

Ведущему: встроенный s17 отвечает текстом XML-кнопки, s18 - desktop-кнопки.
Web по спецификации показывает серверную кнопку и «Продолжить». Необходим
согласованный способ выбора этих разрешённых различий в реальном web-драйвере
или ядре сценариев. Стенд не подменяет тексты и не делает ложного успешного
ответа; до подключения это конкретные потенциально неподдержанные шаги.

После каждого запуска закрываются Edge и клиент со всеми потомками, удаляется
только собственный selftest-узел и сравнивается настоящий session до/после.
Артефакты и журналы сохраняются в новой папке run-UUID для диагностики.

## Проверка инфраструктуры

```powershell
.\ui-parity\Verify-Infrastructure.ps1 -CoreClasses core/target/classes
```

При параллельных изменениях ядра этот режим копирует уже собранный S2 core в
собственную новую папку и компилирует только ui-parity. Без CoreClasses скрипт
компилирует текущие исходники core в изолированную папку, не меняя core/target.
Общий Maven не запускается. Реальная матрица остаётся за явным
`-Dparity.realClients=true` и не включается этим скриптом.

## Передача ведущему, 02.10.2026

Проверка на собранных классах S2: 63 теста обнаружено, 62 успешно, 0 ошибок,
1 assumption выключенной реальной матрицы. Добавлено 18 тестов в этом прогоне.
Отдельный CdpTestApiIT: 1/1 успешно на установленном настоящем Edge. Он проверил
изменение input на синтетической странице, очередь test.step, ошибочный ответ,
отсутствие порта и timeout незавершённого Promise в 150 мс. Это проверка
транспорта и реального DOM синтетической страницы, не интерфейса CashPrediction.
Профиль Edge и вспомогательные процессы освобождены тестами; тесты снимков
удалили собственные узлы и подтвердили неизменность настоящего session.

Реальные FX/Swing/Web сценарии в этой передаче не запускались. Ведущий должен
согласовать PARITY_URL/takeStep с владельцами сервера и страницы, затем выполнить
общую сборку и реальную матрицу. Отдельно проверить web-ответы s17/s18, указанные
выше. Никакой пункт S3/S4 о зелёном UI-паритете этим отчётом не закрывается.
